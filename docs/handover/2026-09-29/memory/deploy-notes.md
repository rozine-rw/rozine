Notes learned standing up [[staging-deployment]] (2026-07-29/30):

- **nginx FastCGI buffers**: Inertia pages emit a very large `Link:` preload header. nginx's default fastcgi buffer is too small and returns **502** on heavier pages (login/register/forgot-password). Fixed globally with `/etc/nginx/conf.d/fastcgi-buffers.conf` (buffer_size 128k, 16x16k buffers) — covers both vhosts. Keep this if reprovisioning.
- **npm lockfile**: `package-lock.json` was macOS-generated and out of sync (`@emnapi/*`), so `npm ci` failed on Linux. Regenerated on Ubuntu and merged via PR #11 → dev → uat (PR #12). `main` still has the OLD lockfile, so the **production** build falls back to `npm install` (the deploy workflow has an `npm ci || npm install` fallback). Promoting uat→main would clean this up.
- **Shared `deploy` user**: staging and production run as the same `deploy` user and share the SSH deploy key / `STAGING_SSH_*` secrets. Isolation gap — a staging RCE could read prod `.env`/files. Acceptable for the waitlist; harden later with a separate `deploy-prod` user + key if prod holds sensitive data. DBs ARE isolated (separate roles/creds).
- **Shared Resend key**: both envs use the same Resend sending key. Fine for now; a prod-only key is a possible hardening. Both this and the shared `deploy` user were re-confirmed on the live host 2026-09-14 — see [[host-isolation-verification]].
- **GitHub deploy keys are disabled** org-wide on rozine-rw/rozine, so the server can't pull from GitHub — pipelines ship code via rsync from the runner.
- **Branch protection** not applied (blocked as a security-setting change); owner can enable requiring the `ci` check on main/uat/dev.
- **Cloudflare** records are DNS-only; enabling the proxy later means Let's Encrypt HTTP-01 renewal needs care (Origin cert or DNS-01).
- Resend test email to erastuskirui01@gmail.com verified **delivered** (staging).
- **Node pinned to exactly 24.15.0 and held** (2026-08-30): Phase 0 set `engines.node: "24.15.0"` (no range operator) with `engine-strict=true` in `.npmrc`, so the box's Node 22.23.2 failed `npm ci` with EBADENGINE and the deploy died. Upgraded via NodeSource (`node_22.x` → `node_24.x` in `/etc/apt/sources.list.d/nodesource.sources`, backup at `/root/nodesource.sources.bak`) and ran `apt-mark hold nodejs`. **Keep the hold** — NodeSource already ships 24.20.0 and the exact pin means any drift breaks deploys again. Node is build-time only here; PHP-FPM serves the apps, so upgrading it disturbs nothing at runtime.
- **Deploys must clear caches before building** (2026-08-30): Wayfinder generates the typed client from Laravel's route list during `npm run build`, and Laravel answers from `bootstrap/cache/routes-v7.php` — which rsync excludes, so it is the *previous* deploy's. Any release adding a route generated a client without it, wiping `resources/js/routes/**` and failing the build on its own imports. Fixed by running `php artisan optimize:clear` after `composer install` and before the build, in both workflows.
- **The remote deploy block is single-quoted**: it runs as `ssh ... 'bash -lc "..."'`, so nothing inside it may contain an apostrophe — one in a comment ends the wrapper early and the build dies with `unexpected EOF while looking for matching`.

- **`public/build` is no longer tracked** (2026-09-06): 75 built asset files used to be committed, because `.gitignore` carried the Next.js template's `/build` rule, which matches only a root-level `build/` — not `public/build`. Every `npm run build` therefore produced a large spurious diff (old hashed files deleted, new ones untracked) that had to be hand-reverted. Now ignored via `/public/build` plus `git rm -r --cached public/build`. Nothing consumed the committed copies: both deploy workflows already rsync with `--exclude 'public/build'` and build on the server, and `tests.yml` runs `npm run build` before `composer ci:check:php`.
- **PHP feature tests need a built Vite manifest**: `resources/views/app.blade.php` uses `@vite`, so a fresh clone with no `public/build/manifest.json` fails the suite with `ViteManifestNotFoundException` → 500, not an obvious error. Run `npm run build` (or `composer setup`, which includes it) **before** `composer ci:check:php`. **Every CI lane that runs the PHP suite must build assets itself** — the PHP 8.4/8.5 quality gates do (`Setup Node` → `npm ci` → `npm run build`), but the PostgreSQL concurrency lane added in #69 did not, and was red on `dev` from the day it landed (24 failed / 140 passed, all `ViteManifestNotFoundException`). Fixed 2026-09-07 in #71. It runs `composer test:php:pgsql` = `pest -c phpunit.pgsql.xml`, the *whole* suite, not just the race tests — so it renders Blade. Copy the four Node steps from the PHP gate into any new lane. This also bites fresh local clones now that the build output is untracked.
- **`composer ci:check:php` needs xdebug/pcov and >128M memory locally**: `test:php:coverage` runs `--coverage --min=100`, so with no coverage driver installed it dies with `No code coverage driver is available`, and PHPStan's parallel workers crash at the default 128M. CI installs xdebug; locally, run `vendor/bin/pest --ci --no-tia --compact` for the suite. The PHPStan half is fixed as of 2026-09-07: `types:check` and `scripts/quality/verify-negative-controls.sh` now pass `--memory-limit=1G`, so `composer ci:check:php:static` runs on a stock php.ini. Only the coverage lane still needs a driver.
- **A local `vp build` rewrites the tracked Wayfinder output** (2026-09-24, PR #103): building in a local checkout or worktree (e.g. to serve previews for screenshots) regenerates `resources/js/{routes,actions,wayfinder}/**` for the local environment. CI fails its "generated output is clean" check after its own build if those diffs are committed. Before committing, run `git checkout -- resources/js/routes resources/js/actions resources/js/wayfinder`, or diff against the base, and never `git add -A resources` after a local build.
